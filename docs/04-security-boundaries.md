# 04 · 安全模型与能力边界

> 本文件是对外可公开的安全说明，也是运营和客服的统一口径。它不是“绝对安全”承诺。
>
> 一句话：**平台做技术托管，不做域名注册商，不做官方实名核验；限流只缓解滥用，公网可达取决于用户基础设施。**

## 1. 资产与信任边界

| 资产 | 存放位置 | 保护 |
|---|---|---|
| 用户密码 | 数据库 | Argon2id（自动 salt），无明文 |
| Access/Refresh JWT | 客户端内存 + Windows Credential Locker（keyring） | 短期 access（15 min）；refresh 轮换、重用即撤销全会话；失败仅内存 |
| 实名状态 | 数据库 | status、审核时间、证件号 HMAC、尾号 4 位；**无原图/明文证件号** |
| 实名原图 | 指定邮箱 | 人工审核后邮箱侧删除，留审计；不进数据库/仓库 |
| 激活码 | 数据库 | 仅 HMAC-SHA256 哈希；全局唯一去重；一次性；失败限次 |
| 证书私钥 | 数据库密文 | AES-256-GCM，`v1:<b64(nonce|tag|ct)>`；主密钥只在环境变量/KMS |
| 证书/链 | 数据库 | 公开材料，可下发元数据；API 永不返回私钥 |
| API 密钥/邮件密码 | 服务器环境变量 | 不入库、不进客户端、不进仓库 |
| 代码签名私钥 | 签名机/HSM | 不进仓库、不进客户端、不交给 AI；`sign.ps1` 只用证书指纹 |
| 用户数据/实名映射 | 私有数据库 | 不进公开仓库；公开仓库仅前端与公开文档 |

信任边界：客户端不可信；公网请求不可信；反向代理之后才信任 `X-Forwarded-For`（`LIULI_TRUST_PROXY_HEADERS=true` 必须配合可信代理，否则可伪造 IP 绕过限流）。

## 2. 账号、人机验证与限流

- 邮箱注册/登录、邮箱验证码一次性；密码 Argon2id；登录失败 10 次锁定 15 分钟（管理员可介入）。
- 算术人机验证：题目/答案只存在服务端；一次性；绑定 `X-Session-Id`；失败即消耗；10 分钟过期；关闭浏览器/重启客户端需重新验证。
- 登录同 IP 20/min、同账号 5/min；注册 3/hour/IP；验证码 30/min/IP；全局限流 600/min/IP、5000/min/实例。
- 域名创建 5/天/用户、总数 20；记录批量 30/hour/domain、单批 ≤200；证书上传 10/hour/domain；实名激活 5/hour/用户。
- 超限返回 429 + `Retry-After`；DNS 层按源 IP/全局 QPS 限速，超限静默丢弃并计数。
- **限流和人机验证只能缓解，不承诺完全防住 DDoS/CC、肉鸡、协议层攻击或 0-day。**

## 3. 实名与激活码

1. 用户在客户端提交证件类型 + 证件号；服务端只保存 `HMAC-SHA256(证件号, DOC_PEPPER)` 与尾号 4 位；不保存明文号码、不保存原图、不做身份证片段映射。
2. 用户把材料发到 `LIULI_REALNAME_INBOX`；后台人工审核通过/驳回。**平台审核不是公安/官方核验。**
3. 后台按 `user_no` 生成一次性激活码；明文只在生成页面显示一次，关闭后不可再取；数据库只存 HMAC。
4. 激活码全局哈希去重、绑定 `user_id/user_no`，状态 `unused/used/revoked`；成功即 `used`，重复使用返回 409；失败次数达 5 次锁定 1 小时，管理员可重置；吊销后不可用。
5. 实名成功后终身有效（平台可因欺诈/司法/注销终止）。未实名不能创建/管理域名；已实名也不能滥用。
6. 原图删除、审计、备份：审核完成后由邮箱侧删除并记录审计；数据库备份不含原图。实名信息不进入 GitHub；公开仓库不含任何真实用户数据。

## 4. 域名、DNS 与公网可达

- 不做注册商、不代注册、不抢注；用户必须先在注册商处取得域名。
- 用户把 NS 指向 `ns1/ns2.<平台域>`，或在注册商处加 `_liuli-verify` TXT；平台验证控制权后才激活。
- 权威 DNS：UDP+TCP 53；**关闭递归**；非托管 zone 返回 `REFUSED`；拒绝 ANY/AXFR；响应过大置 TC；zone 快照缓存 15 秒。
- 支持 A/AAAA/CNAME/TXT/MX/NS/SRV/CAA；CNAME 与其它类型冲突、apex CNAME 等非法组合被拒。
- 公网访问依赖：用户域名有效、NS 委派正确、平台公网 IP/53 可达、目标托管/端口可达、证书有效。任何一环失败都可能不可访问；**不承诺公网绝对可达**。
- 平台自身域名/ API 域名不要由平台 DNS 托管（会拒绝），应在注册商/公共 DNS 配置引导记录与 glue。

## 5. 证书与私钥

- 上传 PEM：校验证书/私钥匹配、域名覆盖、有效期、密钥强度；私钥只在服务端内存短暂处理，随后 AES-256-GCM 加密入库。
- API/日志/错误体/客户端均不返回私钥；`key_cipher` 只存在数据库。
- 主密钥 `LIULI_CERT_MASTER_KEY` 必须 32 字节随机、只放环境变量/KMS；丢失无法解密既有私钥；更换需先做重加密迁移（当前 MVP 未实现自动轮换）。
- 证书到期提醒 30/14/7/3/1 天；用户需上传新证书。ACME 自动签发未启用，API 返回 501 并给手动 DNS-01 步骤。
- 证书链/CA 信任由用户与 CA 负责；平台不代替 CA 审核，不保证所有旧客户端兼容。
- 代码签名私钥只用于签名 EXE/NSIS，不随软件分发；客户端只分发公钥/信任链与说明（如需要）。

## 6. 客户端安全

- 客户端只调后端 API；无硬编码令牌、密钥、证书私钥；API 地址由用户配置，生产要求 HTTPS。
- Token 优先存 Windows Credential Locker；不可用时仅进程内存；不做明文磁盘缓存。
- 崩溃日志本地生成并脱敏（邮箱、密码、Bearer、私钥块、证件号等），弹窗可复制到剪贴板；不上传第三方。
- 本地实验服务只监听 `127.0.0.1`；端口 1024–65535 校验；防火墙放行需 UAC 确认。
- 不做防杀进程、不做对抗用户控制、不做静默提权、不写开机自启、不隐藏后台。
- GitHub 图标只跳转公开客户端仓库；公开仓库不含后端、Token、用户数据；私密仓库不对外跳转。

## 7. 日志与审计

- HTTP 日志 JSON 行、request-id、状态码、耗时；敏感字段脱敏；不记录请求体中的密码/令牌/私钥/完整证件号。
- 审计日志：登录、锁定、实名审核/激活、域名创建/验证/删除、记录批量/回滚、证书上传/替换/删除、后台操作。
- 管理员后台：强密码 + TOTP；登录限流；关键操作写审计；AI 可辅助修复代码，但不自动改生产、不持有生产密钥。
- 日志保留按运营策略与法律要求；不要把生产日志/数据库放进公开仓库或 AI 对话。

## 8. 滥用与处置

禁止：钓鱼/诈骗/赌博/色情/恶意软件、垃圾邮件、侵权、伪造他人域名/证件、DNS 放大、扫描/攻击第三方、绕过实名/限流、存储违法内容。

处置：限流、暂停解析、吊销证书、封禁账号、保留审计并依法配合。平台可紧急处置而无需事先通知。

## 9. 明确不承诺

- 不做域名注册商；不保证注册商允许 NS 委派/glue。
- 不保证公网绝对可达、不保证 100% 可用、不保证绝对无 Bug。
- 不承诺完全防住 DDoS/CC；不承诺永久免费/价格不变。
- 不承诺 SmartScreen 永久无弹窗；坚持同证书签名并引导核对发布者。
- 不承诺恢复丢失的主密钥/被删除的私钥/被注册商收回的域名。
- 不提供防杀进程、对抗用户控制、静默提权或绕过平台安全策略的能力。

## 10. 事件响应

1. 发现疑似泄露：立即轮换 `SECRET_KEY`、SMTP 密码、数据库密码；评估 `CERT_MASTER_KEY` 是否暴露（若暴露需重加密所有私钥并通知用户）。
2. 保留审计/日志证据，不破坏现场；限制管理后台访问。
3. 通知受影响用户与监管/执法（按适用法律）；发布透明的事后说明。
4. 修复后回归：密钥扫描、越权测试、限流测试、备份恢复演练。

## 11. 已验证与未验证

**已验证（Linux 构建环境）**：54 个 pytest 用例；真实 dnslib 权威 DNS 在 5353 的 UDP/TCP A、CNAME、REFUSED、ANY 拒绝；QML 9 页离屏渲染；公开/私有仓库密钥扫描脚本。

**未验证**：Windows EXE/NSIS 构建与 Authenticode 签名（需 Windows 签名机）；真实公网域名 NS 委派；真实 CA 证书链在所有浏览器；大规模压测/多实例 Redis 限流；生产备份恢复演练。发布前必须补做。
